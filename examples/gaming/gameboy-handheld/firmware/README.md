# LabWired Game Boy-compatible handheld

This project runs the MIT-licensed Peanut-GB DMG emulator as STM32F411 firmware. The embedded cartridge is **Wire Runner**, an original 32 KiB homebrew ROM generated by `build_rom.py`. The emulator executes Game Boy SM83 instructions and generates the 160 × 144 display. No Nintendo game or boot ROM is distributed.

## Play

Select **Preview** in LabWired to operate the buttons. Hold the on-screen buttons; descriptive `key` attributes do not establish global keyboard shortcuts. D-pad moves the chip. A doubles movement speed. B resets position and score. Start toggles pause. Select switches the DMG palette. Collect the diamond to score. Button inputs are active-low and use MCU internal pull-ups.

## Hardware interface

| Function | STM32 pin | Carrier connection |
|---|---|---|
| LCD power | 3V3 | J1.1 / VCC |
| LCD ground | GND | J1.2 / GND |
| LCD data | PA7 / SPI1 MOSI | J1.3 / DIN |
| LCD clock | PA5 / SPI1 SCK | J1.4 / CLK |
| LCD select | PA4 | J1.5 / CS |
| LCD data/command | PB0 | J1.6 / DC |
| LCD reset | PB1 | J1.7 / RST |
| LCD backlight | PA8 | J1.8 / BL |
| Up / Down / Left / Right | PB3 / PB4 / PB5 / PB6 | SW1 / SW2 / SW3 / SW4 |
| A / B / Select / Start | PB7 / PB8 / PB9 / PB10 | SW5 / SW6 / SW7 / SW8 |

The display is the Waveshare 2.4-inch ILI9341 module, connected through its PH2.0 cable. The module is 70.5 × 43.3 mm. The firmware programs a 320 × 240 landscape display and scales the DMG image to 240 × 216 pixels, centered at (40, 12).

The carrier is a two-layer 78 × 132 mm board. It uses the upstream WeAct Black Pill v3 physical footprint, the published Waveshare connector order, eight 6 mm through-hole switches, and two bypass capacitors. Its PCB mounts at case coordinates x ±29 mm, y 16 / 132 mm match the shared mechanical interface. Corner notches clear the case closure posts.

USB powers the Black Pill. A panel-mounted USB-C extension/pigtail reaches the case top opening; the MCU module's USB connector is recessed. The enclosure reserves battery and speaker volume, but neither is electrically implemented.

## Validation and limits

Hosted C compilation passes. Direct model verification passes a serial frame oracle, painted LCD, and a right-button input injected through PB6 that changes the emulated player position. The bounded verification runs for 50,000,000 MCU steps. All eight controls have also passed driven STM32 model runs, with each button press and release applied through the circuit. The direction cases change the player coordinates; A produces two-pixel movement steps; B resets position; Start prevents movement until a second press resumes play; Select changes the rendered palette. Exact requests are in `control-vectors.json`, and serial traces, applied-stimulus receipts and oracle results are in `control-validation.json`. The host ROM tests additionally cover all eight controls, score changes, pause, and palette. A live browser test of the local source build shows a correctly oriented 320 × 240 display, Right movement from x = 48 to 63, and button release. Its JSON evidence is `browser-validation.json`; production rollout is checked separately.

Simulation assumes an ideal 3.3 V supply and uses approximate CPU-derived timing. The firmware currently uses the 16 MHz HSI clock and 4 MHz SPI; real-time performance has not been measured on hardware. Power draw, regulator margin, signal integrity, purchased module heights, connector fit, and the printed enclosure require physical validation. Audio, a cartridge socket, save storage, and battery charging are not implemented.

The initial generic LabWired PCB generator produced reference board `pcb_befc6631d9b01f32` with placeholder module footprints and a 123 × 88 mm outline. That board is not the carrier. The separate KiCad carrier files are the electrical manufacturing proposal; their DRC report is included in `../pcb/`.

The saved-project verification endpoint had two generic API defects: combining editable source with a pinned artifact raised `AMBIGUOUS_FIRMWARE_INPUT`; sending this 121,279-byte source inline raised `SOURCE_TOO_LARGE_USE_SOURCE_REF`. Direct source-reference compilation and artifact-based model verification pass. A generic API fix is being reviewed separately.

## Reproduce

Run `python3 build_rom.py` to regenerate the original ROM and C ROM include, then `python3 build_firmware.py` to reproduce the amalgamated hosted source. The full hosted source is `gameboy.c`; `main.c`, `peanut_gb.h`, and `wire_runner_rom.h` are its component sources. The compiled artifact and source-tree digests are recorded in `evidence.json` and `circuit.json`; the ELF binary is omitted from this compact contribution. The 121,279-byte entry exceeds the 64 KiB inline compile limit. Upload it using `labwired_put_source`, then pass the returned `source_tree_ref` to `labwired_compile` with board `stm32f411ceu6-blackpill`, language `c`, and entry `src/main.c`. Use `verification.json` plus the loaded circuit for the driven hosted check. See the root README for the complete source-reference workflow.

For the host ROM behavioral check:

```sh
cc -std=c99 -O2 host_verify.c -o /tmp/wire-runner-host-verify
/tmp/wire-runner-host-verify /tmp/wire-runner-frame.ppm
```
